# 自动化测试

用最少的高价值测试发现风险并建立交付信心。

## 工作流

1. 结合需求、实现和现有测试，明确预期行为、验收边界与主要风险。
2. 选择成本合适且反馈清晰的测试层级，避免在多个层级重复覆盖同一行为。
3. 围绕主路径、边界条件、错误场景和关键交互编写稳定的测试，验证用户可观察结果。
4. 先运行定向测试，再根据影响范围扩大测试范围；区分产品、测试和环境问题。

对于 UI 或交互任务，在条件允许时使用真实浏览器验证实际行为。最终报告测试范围、结果、发现的问题、未覆盖部分和剩余风险。
