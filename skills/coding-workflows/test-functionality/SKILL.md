# 自动化测试

用最少的高价值测试发现风险并建立交付信心。

## 工作流

1. 根据需求、实现和现有测试明确预期行为、验收边界与主要风险。
2. 选择成本合适且反馈清晰的测试层级，避免在多个层级重复覆盖同一行为。
3. 围绕主路径、边界、错误和关键交互实现稳定测试，断言用户可观察结果。
4. 先运行定向测试，再按影响范围扩展；区分产品、测试和环境问题。

UI 或交互任务在条件允许时使用真实浏览器。最终报告测试范围、结果、发现的问题、未覆盖部分和剩余风险。
