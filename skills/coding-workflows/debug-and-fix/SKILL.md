# 调试与修复

用证据缩小范围，修复根因，避免靠堆叠补丁碰运气。

## 工作流

1. 明确预期与实际行为、影响范围和环境，收集错误、日志、近期变化，并尽量得到稳定的最小复现。
2. 沿数据、状态和调用链寻找最早偏差，提出可验证的根因假设，优先验证信息增益最高的假设。
3. 确认根因后实施符合现有设计的最小修复，适合时补充回归测试。
4. 重跑原始场景和受影响检查；假设被否定时回到定位，不累积试探性改动。

最终说明根因、证据、修复、验证和剩余风险；未确认的结论明确标注为推测。
