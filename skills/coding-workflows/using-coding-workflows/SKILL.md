# 使用编码工作流

根据任务的主要目标选择：

- 开发前验证方案或降低技术不确定性：`assess-technical-feasibility`
- 实现项目、功能或行为变更：`spec-driven-development`
- 验证功能、接口、UI 或交互：`test-functionality`
- 定位并修复已有问题：`debug-and-fix`

必要时按依赖组合，例如先评估再开发、开发后测试、修复后回归。
