# Spec 驱动开发

以可验证的 Spec 明确方向，用 Plan 和 Todo 推进交付；TDD 是提高关键行为质量与交付信心的辅助手段。

## 工作流

1. 理解项目和需求，明确目标、边界、约束与可验证的验收标准；只有未决问题会影响范围或方案时，才向用户确认。
2. 将 Spec 拆成按依赖排序、可独立验证的计划与 Todo，优先交付可运行的纵向切片。
3. 沿用项目现有模式实现；对关键逻辑、边界条件和回归风险按需使用 TDD，并持续进行定向验证。
4. 根据影响范围执行测试、构建或其他检查，对照 Spec 完成验收，并说明实现内容、验证结果与剩余风险。

根据任务规模裁剪流程，不追求形式完整或测试数量，也不扩展无关范围。

除非用户或上层指令明确要求，否则不要使用子智能体（sub-agent）。
