# Spec 驱动开发

以可验证的 Spec 约束方向，用 Plan 和 Todo 推进交付；TDD 是提高关键行为质量的辅助手段。

## 工作流

1. 理解项目和需求，明确目标、边界、约束与可验证的验收标准；只确认会改变范围或方案的关键问题。
2. 将 Spec 拆成按依赖排序、可独立验证的计划与 Todo，优先交付可运行的纵向切片。
3. 沿用项目现有模式实现；对关键逻辑、边界和回归风险按需使用 TDD，并持续做定向验证。
4. 按影响范围运行测试、构建或检查，对照 Spec 验收并说明完成内容、验证结果与剩余风险。

根据任务规模裁剪流程，不为文档、测试数量或无关扩展制造工作量。
